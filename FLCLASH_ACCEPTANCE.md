## Safe result available now

`scripts/flclash_acceptance.py` is an offline checker, with no process launch, sockets, network inspection, installation or execution mode. With no arguments it prints the pinned plan. With three arguments it reads two JSON configuration snapshots and checks the narrow fixture contract:

```powershell
python -B scripts/flclash_acceptance.py
python -B -m unittest discover -s scripts -p test_flclash_acceptance.py -v
python -B scripts/flclash_acceptance.py --original-json original.json --effective-json effective.json --proxy-target LAB
```

The original must be the untouched synthetic profile from that refresh revision. The effective snapshot must later be captured from the app-generated YAML and losslessly parsed to JSON. The checker requires exact original-rule order, exactly two TCP 443 managed rules before the terminal MATCH, unchanged DNS/proxies/groups, loopback controller 9090, TUN and LAN disabled, original providers preserved except their app-owned paths, and managed HTTP providers at `127.0.0.1:18765` with explicit `proxy: DIRECT`. For this fixture use the same provider definitions as `smoke_observe.py`, not `tail-preview`'s disconnected local-file placeholders.

Passing the checker says only `config_contract_passed: true`; it always says `app_tested: false` and `tun_tested: false`. It does not prove snapshot provenance, app state, provider file existence, runtime behavior or cleanup. Tests use invented in-memory fixtures and must never be published as observed application evidence.

## Offline GUI diagnosis and repair (2026-10-08)

The old helper waited for a nonzero HWND and performed exactly one query. That does not establish that a Flutter semantic tree was ready. The failed run retained no tree or screenshot, so the exact runtime cause remains unknown. Source at the pinned release declares sidebar `Semantics(container: true, button: true, selected: ...)`, an InkWell tap action and label text with `alwaysIncludeSemantics: true` ([sidebar.dart](https://github.com/chen08209/FlClash/blob/68c71b8ef9b7486a224972eb371ff153c6b2de0f/lib/widgets/sidebar.dart#L395)). English localization is `Profiles`; the fixture seeds locale `en`, but that run never read the persisted locale after launch. A collapsed sidebar alone is not source evidence that the label disappears. The native runner defers visibility to application code; an HWND alone does not prove visibility.

No explicit `ensureSemantics` call was found in the pinned app sources. This does not prove accessibility was disabled at runtime. The declared Flutter 3.47.4 engine source could not be retrieved at that tag (404); do not substitute another engine version as release evidence. Windows documents that normal UIA/MSAA client calls request accessible objects through WM_GETOBJECT ([Microsoft](https://learn.microsoft.com/en-us/windows/win32/winauto/wm-getobject)). The repaired helper uses AccessibleObjectFromWindow for owned HWNDs and UIA raw-tree polling, records request HRESULTs and leaves `semantics_enabled` explicitly unknown. An HRESULT alone does not prove Flutter semantics were enabled.

The selector still requires exactly one visible, enabled, owned-process Invoke control. Button semantics justify retaining Invoke; no observed release tree justifies guessing SelectionItem/LegacyIAccessible, coordinates, translated labels or keystrokes. The helper now waits up to 15 seconds, records up to 256 raw-tree entries with supported patterns, visibility/minimization, persisted locale and an owned-window PrintWindow screenshot (PNG <=512 KiB encoded in the existing synthetic result log). PrintWindow success is not proof of a nonblank Flutter image. Screenshot failure or helper timeout is recorded, never a pass; no whole-desktop capture, artifact upload or accessibility system-setting change is introduced. Normal parent timeout is 40 seconds. Forced cleanup now waits for each recorded process to exit.

Offline selector tests cover wrong process, hidden/disabled/non-invokable controls, exact language labels, empty trees and ambiguity. PowerShell parsing and C# helper compilation make no UI calls. Real accessibility activation, UI patterns, screenshot readability and app refresh remain untested after these changes.

It never silently resumes learning, and refuses refresh/recovery if old-process exit is unconfirmed. It is an interface boundary, not a connected FlClash supervisor: the actual configuration-owner adapter, fresh-lease issuance, guarded crash recovery implementation and process supervision integration remain open. No new automatic CLI/startup behavior is enabled.
