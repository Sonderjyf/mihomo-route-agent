## Offline DNS diagnosis and strict fixture repair

The fixed app source calls [handleGetConfig](https://github.com/chen08209/FlClash/blob/68c71b8ef9b7486a224972eb371ff153c6b2de0f/core/hub.go#L749), which calls `UnmarshalRawConfig` before script evaluation. Its pinned core submodule is `8597778c7df410ebe88c57e59eaab32d203156df`. [RawDNS](https://github.com/chen08209/Clash.Meta/blob/8597778c7df410ebe88c57e59eaab32d203156df/config/config.go#L221) has 27 JSON fields without `omitempty`; [default initialization](https://github.com/chen08209/Clash.Meta/blob/8597778c7df410ebe88c57e59eaab32d203156df/config/config.go#L505) precedes [YAML parsing](https://github.com/chen08209/Clash.Meta/blob/8597778c7df410ebe88c57e59eaab32d203156df/config/config.go#L607). The app JSON-serializes this structure. Enabled DNS with `overrideDns=false` and `appendSystemDns=false` retains it in [profile generation](https://github.com/chen08209/FlClash/blob/68c71b8ef9b7486a224972eb371ff153c6b2de0f/lib/common/task.dart#L247). The pinned [YAML writer](https://github.com/chen08209/yaml_writer/blob/79c78a44ec9c2f5f5f97da1a65610c6fb2ead8b3/lib/src/node.dart) preserves null, empty-list and empty-map values.

Thus the original four-field DNS fixture was an invalid exact-comparison baseline: normal typed serialization adds 23 fields, including `use-hosts=true`, `use-system-hosts=true`, `ipv6-timeout=100`, `fake-ip-range=198.18.0.1/16`, filter defaults and nil policy/fallback fields. This mechanism is **confirmed from source**. A standalone, offline Go model extracted the DNS structure/defaults/text codecs and reproduced all 23 additions. Its JSON input and ordinary map substitutes mean it is a serialization reproduction, not the bundled YAML parser or actual app. Complete model inputs/outputs and limits are in [offline evidence](evidence/windows-flclash-dns-offline-2026-10-08.json). Normal materialization is the strongest supported explanation of the historical error; without the missing actual snapshot, additional app-setting overrides cannot be excluded. There is no demonstrated product-export or overwrite-script DNS mutation.

The synthetic subscription now explicitly supplies all 27 DNS fields and empty `proxies`, another typed default. FakeIP mode/range/default filters are preserved. All resolver addresses, including bootstrap DNS, are explicitly loopback; a synthetic `.test` nameserver policy exercises policy retention. Empty collections are explicit. This changes only the acceptance fixture, not user configuration or the product exporter. The new fixture roundtrips exactly through the source-derived serializer. The checker still rejects **every** unexpected DNS addition/removal/value change; it does not discard defaults or ignore selected fields. It now also distinguishes boolean/integer types and missing/null. Rule order, TCP 443 scope and exactly-once tails retain their original checks.

Before any contract assertion, the app harness records full synthetic DNS expected/actual values and JSON Pointer differences in the final result log/file, retaining only the latest snapshot per A/B revision. Failure therefore leaves inspectable values without an artifact upload. Regression tests cover the old sparse mismatch, fixed explicit baseline, snapshot persistence, DNS/FakeIP/policy changes, list order, types and unexpected fields. These are offline guards, not proof that application refresh works. A further actual app attempt remains blocked pending a separate single-run approval; no standing approval was saved.

The application job uses the standard `windows-2025` runner, 20-minute limit, no larger runner, artifacts or cache actions, and no model API.
